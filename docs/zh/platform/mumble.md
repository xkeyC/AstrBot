# 接入 Mumble

Mumble 适配器以机器人身份连接 Mumble 服务器（1.5 及以上），在频道和私聊里收发文字；开启实时语音后，还能在频道里用语音对话（全双工），语音由 Codex 实时语音驱动。

## 创建 AstrBot Mumble 平台适配器

进入 `机器人` 页面，点击 `+ 创建机器人`，选择 `Mumble`，打开 `启用` 后填写：

- `Mumble 服务器地址`、`Mumble 端口`（默认 `64738`）
- `机器人用户名`：机器人在 Mumble 里显示的名字
- `服务器密码`：服务器设了密码，或机器人已注册账号时填写
- `初始频道`：连接后进入的频道名，或从根频道起的路径（如 `游戏/闲聊`）；留空则留在默认频道
- `频道文字唤醒前缀`：默认 `!`，见下文

首次连接时会在 `data/mumble/<平台 ID>/` 下生成客户端证书，服务器据此识别机器人。管理员可以在 Mumble 客户端里注册机器人账号、授予权限；也可以在 `客户端证书` 里指定自己的证书。

## 会话与唤醒

- **整个服务器是一个群聊会话**（会话 ID `server`），机器人在哪个频道都不影响上下文。管理员可以随时把机器人拖到别的频道，回复会发到消息所在的频道。
- **私聊**按用户各自一个会话。用户 ID 取客户端证书哈希（官方客户端都有证书），配置管理员时填这个哈希；没有证书也没注册的用户只在本次连接内有效。
- Mumble 没有 @ 功能。**频道文字以唤醒前缀开头**（如 `!今天天气怎么样`）才会唤醒机器人，等同于 @ 机器人；私聊总是唤醒。全局唤醒前缀（如 `/` 指令）照常可用。

## 实时语音

需要 `Codex Agent 执行器` 登录**包含语音功能的 ChatGPT 订阅账号**。语音通过 WebRTC 连接 Codex 实时语音，不需要 API Key。

- 有人在机器人所在频道说话时自动接入。频道里**只有叫到机器人的名字才会回应**：这由提示词约束，偶尔可能插话。**对机器人私语**（whisper）总是回应，回复也以私语发回。
- 语音里交办的事情由独立的**语音 Agent 线程**处理：频道语音和每个私语对象各自一个线程，按会话持久化复用；不挂 AstrBot 工具、没有执行环境，访问不到其他会话。它遵守执行器配置的模型、推理强度、联网搜索、沙箱等限制，不启用子 Agent 和 ChatGPT 连接器。执行器开启记忆时，它可以读取全局记忆和配套会话的记忆（频道语音对应服务器群聊，私语对应该用户的私聊），但不能写入或删除全局记忆。（如果开启了“会话隔离”（`unique_session`），群聊会按用户拆成多个会话，频道语音对应的仍是整个服务器那一个群会话的记忆。）
- **待机**：连续 `语音待机时间`（默认 300 秒）没有识别到语音，就断开实时语音；检测到新的人声时自动恢复，恢复时会补上刚才那句话。
- **闭麦 / 开麦**：在频道里发送 `唤醒前缀 + 闭麦`（或 `mute`，也可以用全局唤醒前缀），私聊里直接发 `闭麦`，机器人就不听也不说，并显示为静音；发 `开麦`（`unmute`）恢复。闭麦超过 1 分钟会断开语音会话。
- 可配置的语音选项：`语音唤醒名` 和 `语音唤醒别名`、`音色`（juniper、maple、spruce、ember、vale、breeze、arbor、sol、cove，默认 cove）、`实时语音模型`、`语音附加提示词`、`语音 Agent 指令`。

## 部署 Mumble 服务器

可以直接使用官方镜像：

```bash
docker run -d --name mumble-server -p 64738:64738/tcp -p 64738:64738/udp mumblevoip/mumble-server
```

首次启动的日志里会打印 `SuperUser` 的密码。机器人只使用 TCP 连接（语音也经 TCP 隧道传输），无需额外开放端口。
